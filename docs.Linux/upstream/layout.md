# Upstream layout ↔ this repo (one row per upstream project)

**English** | [中文](layout.zh-CN.md) | [Español](layout.es.md)

> Part of **docs.Linux** — back to the [port-side docs bus](../README.md) ([中文](../README.zh-CN.md) · [Español](../README.es.md)).

**The question this page answers**: for a given upstream `dotnet/wpf` project, **where did it land in this repository** (who compiles it, who overrides it).

- **Upstream snapshot**: `upstream/wpf/` (read-only, the build input; base `1cfc37f708f91ff4556bd25af414546c446f3a16`, criteria in [`docs/UPSTREAM-PROVENANCE.md`](../../docs/UPSTREAM-PROVENANCE.md)).
- **The build here is generative**: `build/port-lib.py` **reads source** from `upstream/wpf/**` and **rewrites** `build/<Project>.Linux/<Project>.Linux.csproj` wholesale — so one upstream item usually maps to **three places**: `upstream/wpf/**` (read-only source), `build/<Project>.Linux/**` (the generated build project) and the overlay (`src/WpfGfx.Linux*/**`, `build/shims/**`, appliers `patch-*.py`).
- **Caliber**: rows are the **project subtree directories** under `upstream/wpf/src/Microsoft.DotNet.Wpf/src/`; the `Directory.Build.Props` **file** in that directory is deliberately not a row (it is read level by level by `port-lib.py`'s `upstream_nowarn()`).

## Re-computing the caliber of this table

```bash
# (1) project subtree directories (the row count of this table): expect 21
ls -d upstream/wpf/src/Microsoft.DotNet.Wpf/src/*/ | wc -l
# (2) entries in that directory (= project subtrees + the Directory.Build.Props file): expect 22
ls upstream/wpf/src/Microsoft.DotNet.Wpf/src/ | wc -l
# (3) rows in this table: expect 21
grep -c '^| `upstream/wpf/src/Microsoft.DotNet.Wpf/src/' docs.Linux/upstream/layout.md
```

⚠️ **Stated plainly**: `ls … | wc -l` reads **22** because that directory also holds one **file**, `Directory.Build.Props` (136 B), besides the 21 project subtrees.
This table lists the **21 project subtrees**, so `(1)` and `(3)` agree and both differ from `(2)` by exactly one — that props file.

## Boundaries and what is not on this table

- **`build/*.Linux/` is generated**: `port-lib.py` **rewrites** the csproj wholesale, so hand-edited wiring is erased; wiring must live in the **appliers** (`src/WpfGfx.Linux.Native/tools/patch-*.py`).
- **Hand-written projects** (not regenerated): `DirectWriteForwarder.Linux`, `System.Printing.Linux`, `System.Windows.Extensions.Linux`, `CycleStub.*`, `build/DirectWrite.Linux/Provider/`, `src/WpfGfx.Linux/`. Source: `build/integration-wave.sh:106-107`.
- **There is no second copy of the Windows source at the root any more**: the WPF tree the fork root used to carry was removed in `7027be06e` (P0 de-duplication, 19 paths); the reasoning and re-computation are in `build/MilBridge/P0-migrate-report.md`.
