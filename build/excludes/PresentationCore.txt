#   PointUtil.cs / SafeSecurityHelper.cs / exports.cs / wgx_commands.cs /

# D 类：模块初始化器（Windows-only 原生预装载）—— 剔除
# ---------------------------------------------------------------------------
# ModuleInitializer.cs（PresentationCore 的 [ModuleInitializer]，36 行）
#
# 实测证据（/tmp/m4/oleprobe，硬证据）：只要**触碰 PresentationCore 的任意类型**，
# `<Module>` 的静态构造就抛
#     TypeInitializationException -> DllNotFoundException:
#     Unable to load shared library 'user32.dll' or one of its dependencies
# 因为该初始化器第一条就是 `IsProcessDpiAware()` → `[DllImport("user32.dll")]
# SetProcessDPIAware_Internal()`；随后还有 `DWriteLoader.LoadDWrite()`
# （NativeLibrary.Load("dwrite.dll")，Linux 上同样必然抛 DllNotFoundException）。
# 即：**不剔除它，PresentationCore.dll 在 Linux 上根本无法加载**（编译期完全看不出来）。
#
# 剔除依据（Linux 上这三件事都无对象可做，不是"砍功能"）：
#   1. SetProcessDPIAware：Windows 的 DPI 感知是 Win32 概念，Linux 无对应语义；
#   2. DWriteLoader.LoadDWrite/UnloadDWrite：装载的是 Windows 的 dwrite.dll；
#      Linux 侧文本栈由 M1 Skia 承接，且 DWriteLoader 自身仍可被显式调用
#      （它就是"装载失败即抛异常"的诚实实现）；
#   3. MS.Internal.NativeWPFDLLLoader.LoadDwrite()：上游本就是空实现（保留方法锚点）。
# 编译期安全性：`ModuleInitializer` 类型**无任何其它引用**（已 grep 全树确认为空），
# 剔除后 0 新增错误、0 新增警告（实测）。
#
# 恢复条件：Linux 侧文本栈确定后，若需要"加载失败即报错"的早期失败语义，
# 可改为在 PresentationCore 之外（宿主/测试）显式调用 DWriteLoader.LoadDWrite()，
# 而不是恢复该模块初始化器；
# 另一条路线是提供 ELF 形式的 `user32.dll`/`dwrite.dll` 原生占位（不推荐：伪造的
# user32 会掩盖真实的 API 缺失，且与本项目"宁可抛异常也不假成功"的口径冲突）。
PresentationCore/ModuleInitializer.cs
