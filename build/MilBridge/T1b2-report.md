### 1.2 每一列都标来源（主控裁定 ③）—— 五类标记 + 图例 + 逐条 `依据=`
```
[ROWD] 列来源图例（**每一列必属其一**；D/E 结局靠它判）：
[ROWD]   [O]  = 我们侧·实读：直接读 `HbTextLine` 契约属性 / 反射读 `_charAdvances`

[ROWD]   [X]  = 跨侧对照：把我们判据套在真值文本上 —— **它不是真值**，只用来显示口径差

```
**唯一一处 `[Td]`（推导）就是整个判定的支点，规则写死为**：**真值可见尾空白 = `ws − nl`**（真值 `ws` 含 换行/EOP ⇒ 减去 `nl` 才是"可见文本的尾空白数"）。逐字符列一律 `[NA]`。
每条 `VERDICT` 后面跟一行 `[ROWD] 依据=…`，逐条说明**这条判定用了哪几类列**，例如：
```
[ROWD] 依据=ws[T] / WITW−W[T]/[O] / 尾部可见空白[Td:ws−nl]/[O] / 逐字符 advance[O] —— **[NA] 列未参与**（不需要）
```
⇒ **D/E 结局因此真的可判**：D 只说"仪器自身状态"（未用任何真值列），E 明写"需要逐字符真值 `[NA]`，而该列不存在"。

### 1.3 ⭐ 仪器的自我更正（登记）

### 2.2 机制二 · C（`与` 的字形/advance 选取）—— 3 行，**根因已闭环**
`A1_nbsp_zwsp_w20#7`、`F_nbsp_zwsp_w40#3`（行文本都是 `'与 '`）、`B_nbsp_zwsp_trim#1`。**三条都含 `与`**。
`ws` 与 `WITW−W` 两侧**完全一致** ⇒ **不是空白口径**；而 `adv_ours 和 − 真值 WITW = −6.4000 / −6.4000 / −6.7167`（≠ 任何单字符 `adv_ours`）。
根因三段，**逐位可复算**：
```
① file 字体里没有 U+4E0E：build/fonts/NotoSans-Regular.ttf 的 cmap 查 U+4E0E → glyph None
   （对照：U+0020→3、U+00A0→98、U+200B→566 ⇒ 不是"字体整体读不出来"）
② hmtx：glyph 0 (.notdef) advance = 600 units / upem 1000 = 0.6 em ⇒ @fontSize 16 = **9.6000 DIP**
   == 我们实测 `c=0 U+4E0E 与 adv_ours=9.6000` ✅（其余逐字符 advance 也逐位对得上：
      n=9.8880=618u、NBSP/space=4.1600=260u、ZWSP=0.0000=0u）
③ 真机 `与` = **16.0000 DIP = 1.0000 em** = 全宽 CJK 字面
```
⇒ **我们画的是 `.notdef`（0.6 em），真机用的是 CJK 回退面（1.0 em）**。`B_nbsp_zwsp_trim#1` 的 `6.7167 = 6.4000 + 0.3167`（多出的 0.3167 < 0.34 是拉丁字母的亚像素量化余差，有逐字符实测支撑）。
旁证：同行 `Extent` 我们 `13.4240` / 真值 `16.0859`（Δ=−2.6619）⇒ 墨迹盒也不同，**不是同一个字形**。
**为什么值钱**：`F_nbsp_zwsp_w40#3` 正是 (b) 契约①那条负宽行（`cr.Width = −3.0560`）；它的根因是这个错的 advance，**不是空白、也不是折叠**。主控已据此把机制二**单列在册为 `D-F1`**（不塞进 `#12`）。

## 9 · 🔴 仪器缺陷（主控派：T1d 现场证据）—— `ShimSha256()` 读的是**盘上路径**，不是**编进去的那一份**

### 9.1 缺陷
```csharp
// Program.cs（本轮**未改**这一处；此处照抄原状）
private static string ShimSha256()
{
    // ⚠️ 必须取**编译进本 harness 的那一份**：`-p:HbShimSrc=` 可以指向别的路径（staging 副本）…
    string p = Environment.GetEnvironmentVariable("T1B_SHIM_PATH") ?? Path.Combine(Root, HbShimSource.File);
    ...
}
```
**"真正编进去的那一份"由 `-p:HbShimSrc=` 决定**；而这个函数取的是 **`T1B_SHIM_PATH` 环境变量 ?? shim 源里那个常量路径 `build/shims/PresentationCore.HbTextLine.cs`**。
⇒ 当有人**用 `-p:HbShimSrc=/tmp/…`（内容 = `b4c7aa82`）编、却没设 `T1B_SHIM_PATH`** 时：`gen/tline-detail-full.txt` 头行印出 **`3081D088…`（仓库源，T1d 的在改版）**，而同一行还写着"**本 harness 直接编入**" ⇒ **头行读的是源盘路径、不是编进去的那份**，且**标签把这件事说反了**。

### 9.2 为什么现有自检拦不住（这是最要紧的一点）
`T0.4` 与 `T0.6` **也落在同一个常量路径上**：
```csharp
string shimPath = Path.Combine(Root, HbShimSource.File);   // T0.4 算 sha
Check("T0.4", …, sha.Length == 64, $"{HbShimSource.File} sha256={sha}");
Check("T0.6", "被测文件的 sha256 == run.sh 固定的 sha256", pinned == sha, …);
```
⇒ `ShimSha256()`、`T0.4`、`T0.6` **三者一致地都读盘上那个路径** ⇒ 换 `-p:HbShimSrc` 时它们**一起骗人**（三者互相印证 ⇒ `T0.6` 也拦不住）。`HbShimSource.File` 是**shim 源里的常量**，它记的是"这份源**认为**自己在哪"，**不是编译器实际收到的那份文件**。

### 9.3 正确修法（**写进报告，不在本轮落**）
1. **构建期把 `$(HbShimSrc)` 的 sha256 落成生成常量**（MSBuild `WriteLinesToFile`/自定义 target 写一个 `.g.cs`，例如 `internal const string CompiledShimSha256 = "…";`），**运行期印那个值** —— 它按构造就是"编译器真正收到的那一份"。
2. 头行**禁止**用"运行期 env + 默认相对路径"去**推断**"编进去的是哪一份"；env 只允许作为**显式断言锚**（对不上就大声失败），不允许作为**取值来源**。
3. `T0.4/T0.6` 改为核对**生成常量** vs `T1B_SHIM_SHA256`。

### 9.4 用法说明（**下一个人别再踩**）
> **`T1B_SHIM_PATH` 与 `-p:HbShimSrc` 必须指向同一个文件。**
> - 用 `bash build/MilBridge/run.sh tline` 时：`run.sh` 把 `SHIM="$MB/../shims/PresentationCore.HbTextLine.cs"` 同时用于 `-p:HbShimSrc="$SHIM"` 与 `T1B_SHIM_SHA256="$SHA"`，**但它不设 `T1B_SHIM_PATH`** ⇒ 走默认路径常量 ⇒ **两者一致，安全**。
> - **手工**跑（尤其做牙/换 staging 副本）时：**要么别传 `-p:HbShimSrc`**，**要么把 `T1B_SHIM_PATH` 设成同一个绝对路径**。只要这两个不一致，头行/`T0.4`/`T0.6` 报的就不是被测的那一份。
