## Q2_is_one_em_a_rule_or_a_property_of_the_substituted_glyph
Q: The field case saw exactly 1 em for the missing glyph. Is '1 em' the rule for a missing glyph, or a property of whatever glyph got used?
A: It is a property of the substituted glyph, not a missing-glyph rule. The same table shows missing code points whose advance is 1 em (CJK: the substituted font's ideograph is full-width) and missing code points whose advance is the paragraph font's .notdef width instead (private-use code points, 18.000000 / 18.666667 / 14.400000 DIP), and present code points at 1 em as well (Arial's own U+2192 is exactly 1 em). Nothing in the data supports a fixed width for a missing glyph.

## Q3_can_a_client_observe_which_font_was_actually_used
Q: Can the actually-used font / glyph be observed through the PUBLIC API?
A: YES, through the public API, no reflection needed: TextLine.GetIndexedGlyphRuns() returns IndexedGlyphRun objects, each carrying the character range and a GlyphRun whose GlyphTypeface (-> FontUri) and GlyphIndices are the font and glyph really used. Every 'observedFont' / 'observedGlyphIndex' column in this oracle comes from that API. Note that the run's GlyphTypeface can be a DIFFERENT font from the one in the paragraph's TextRunProperties - that is exactly how the fallback is detected.
